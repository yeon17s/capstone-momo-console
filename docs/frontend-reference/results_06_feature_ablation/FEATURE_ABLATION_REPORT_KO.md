# voraus-AD 공통 특징 후보별 효과 분석 — 2026-10-17

## 1. 분석 목적과 기존 A/B/C 실험의 한계

기존 A는 전체 전류·전압16특징, B는 위치·속도 원신호와 오차를 함께 더한304특징, C는 iq를 더한352특징이었다. B 내부 그룹의 효과와 전압 의존성을 분리해 보기 위해 신호 그룹 단독·G0 추가·B에서 제거·원신호와 오차 표현을 비교했다. 최고 성능 탐색이나 하이퍼파라미터 최적화가 목적이 아니다.

**모든 결과는 기존 EDA/Baseline 평가 데이터를 다시 사용한 탐색적 비교다. 새로운 독립 검증 성능이 아니다.** 가장 높은 행을 선택해 xArm 성능이나 물리적 고장 원인 학습을 입증할 수 없다. 평가 단위는 전체 사이클 종료 후 판정이며 Action·조기 탐지·미래 위험·RUL은 이번 범위에 없다.

## 3. 데이터 분할 및 모델 설정

- 기존 `cycle_split.csv`의 sample 배정을 그대로 재사용: PRE_A 정상948 중 fit711 / 임계값 검증237. 평가 정상419+이상755=1,174. 행이나 윈도우를 섞지 않고 사이클을 분리했다.
- 기존 `cycle_features.parquet`의2,122×352 특징을 열 선택해 재사용했다. 이 캐시는 각 사이클 내부에서 계산한 결정적 통계이며 전체 데이터로 fit한 scaler가 아니다. 원시 Parquet을 다시 읽거나 오차 정의를 변경하지 않았다.
- `baseline_core.Detector`와 `calibrate_threshold`를 그대로 import했다. StandardScaler·분산1e-12 이하 열 제거는 fit 정상에서만 수행. 실제 유지 차원을 각 결과 행과 `feature_catalog.csv`/모델에 기록했다.
- 통계 점수=표준화z² 평균. IF=200 trees/max_samples256/contamination auto/seed 20261015. PCA=학습 설명분산95%, full SVD, 재구성MSE. 모델 설정과 점수 방향을 바꾸지 않았다.
- 조합마다 검증 정상237개의 k=227번째 점수로 임계값을 정하고 `score > threshold`로 판정했다. 목표 검증 FPR5%, 관측 검증 FPR은 각 행에 저장. 배치 이동에서의 5% 보장은 없다. 검증 후948개로 재학습하지 않았다.
- 주 지표는 이상 유형별 AUROC(각 유형 vs 같은 정상419개)의12종 동일 비중 평균. pooled AUROC는 보조다. 유형별 Recall도 모든 모델에 공통인 해당 조건의 고정 임계값을 사용했다. 배치별 FPR에는 오탐 수/분모/Wilson95% 구간을 저장했다.
- 기존 A/B/C의 Cycle9조건은 점수·threshold·판정·지표를 비교했다. 재현 통과 9/9, 최대 점수 절대 차이 3.55e-15, 판정 차이 총 0개. 숫자 차이를 감추려고 설정을 조정하지 않았다.
- 실행 환경과 코드 hash, 캐시·분할 hash, 고정 조합은 `frozen_ablation_protocol.json`에 기록했다. 기존 코드/보고서/CSV/학습 모델은 실행 전후 SHA-256으로 보존 여부를 확인한다.

### 질문2. A 통계 모델의 높은 마찰 AUROC와 전압 의존성

마찰 집단의 **평균 통계 점수 중 전압 특징의 z² 기여 비중은 89.8%**였다. 이는 기존 G0/통계 점수의 유지 특징별 z²를 동일 가중치로 합한 점수를 분해한 값이다. AUROC의 인과적 기여율이나 센서 제거 시 성능 감소율이 아니다. current/voltage 단독 성능과 같이 보아야 한다.

`statistical_group_contributions.csv`는 모든 입력 조합에서 전류·전압·각 관절 그룹이 점수에 얼마나 기여했는지 fit/검증/각 이상 유형/정상 배치별로 기록한다. 전압 영향이 다른 그룹 추가 후 얼마나 희석·유지되는지도 볼 수 있다. 이 진단은 점수 설명이며 물리적 원인을 확인한 결과가 아니다.

### 질문7. 특징 수 증가와 알고리즘 차이

예를 들어 G0의16유지 특징에서 기존 B의289유지 특징으로 늘릴 때 Statistical Macro는 0.797→0.677로 낮아졌지만 PCA는 0.637→0.824로 높아졌다. B에서 G1/G2를 제거하면 Statistical/IF의 Macro가 높아지는 반면 PCA는 낮아졌다. 특징 수의 증가 자체로 일관된 개선이 나타나지는 않았다.

차원 증가가 같은 효과를 보장하지 않는다. Statistical은 유지 열의 z² 평균이므로 중복된 양수 신호 mean/abs_mean 및 유사 RMS를 반복 가중하고, 많은 낮은 점수 열이 핵심 신호를 희석할 수 있다. IF는 무작위 분할에 쓸 후보 축과 상관구조가 바뀌며, PCA는 유지 차원과 잔차 부분공간이 달라진다. 어느 알고리즘의 감소를 센서의 무용성으로 단정하지 않는다. 실제 차원·PCA 차원은 전체 표와 모델에 기록했다.

또한 원시 target/joint 차분을 요약한 오차는 원신호의8개 통계만으로 정확히 복원되지 않을 수 있어, G3/G4가 파생 정보라도 현재 요약 표현에서는 도움이 될 수 있다. 원신호와 오차의 상관·의존을 분리한 인과 실험은 아니다.

## 8. xArm 적용을 위한 공통 특징 후보 우선순위

### 질문9. 수령 전 검토 우선순위

아래 우선순위는 최고 AUROC 순서가 아니라 **예정 계측 구성, 신호 확보 가능성의 확인 순서, 배치 안정성과 해석 가능성**에 따른 제안이다. 실제 xArm API·센서 주기·동기화는 미확인이고 전이 성공을 전제하지 않는다. 아직 센서를 직접 연결하지 않았으므로 INA226도 실측 가능성이 검증됐다고 쓰지 않는다.

전류·전압을 함께 기록하고 전원 조건을 추적하는 것이 우선이다. 위치 목표/피드백 API를 확인한 뒤 원신호와 오차를 동시에 보존해 표현을 비교한다. 속도는 읽기 주기 또는 위치 차분의 잡음·지연 검증 후 검토한다. iq는 현재 외부 센서의 대체 목표가 아니라 산업용 참고 축으로 둔다. 향후 이 데이터로 조합을 고른다면 신규 xArm 세션에서 설정을 고정한 독립 평가가 필요하다.

## 9. 분석의 한계 및 후속 실험 제안

### 질문10. 확인한 사실과 가설의 구분

**확인:** 동일한 기존 split/설정에서72조건을 평가한 지표 차이, A/B/C9조건 재현, 배치별 오탐 수, 통계 점수의 특징별 z² 기여다. 각 조건의 preprocessing/threshold는 정상 fit/검증만으로 정했다.

**가설:** 전압 차이가 특정 수집 배치·전원 환경을 반영한다는 해석, 특정 관절 오차가 제어기 보상 때문에 작다는 설명, 공통 특징이 다른 로봇에서 유용할 것이라는 기대다. 이번 그룹 제거·추가만으로 물리적 원인이나 전이 효과를 검증하지 못했다.

- 동일 평가 데이터를 EDA·Baseline·이번72조건 비교에 반복 사용했다. 검증 정상만으로 threshold를 정해도 이러한 연구자 선택 편향은 제거되지 않는다. 가장 좋은 행은 탐색적 후보일 뿐이다.
- 단일 seed이며 반복 배치 내 사이클 상관·다중 비교를 보정하지 않았다. 표의 작은 차이를 통계적 유의성으로 표현하지 않는다. 유형0~11의 수가 다르고 정상 배치76은19개다.
- PCA가 유지 특징 전체를 보존하면 재구성 오차가 거의0일 수 있다. `pca_components`와 retained 차원을 함께 보고 해석한다. 결과가 불리하다고 n_components를 바꾸지 않았다.
- 캐시는 기존 정의의 사이클 요약이다. 신호 간 위상·국소 이벤트·시간 추세의 모든 정보를 담지 않는다. Action 분석은 수행하지 않았다. 필요시 동일 그룹 선택 함수를 Action 테이블에 적용하는 별도 고정 실험을 설계한다.
- 실제 xArm은 관절 구성·제어·피드백·주파수·전원·센서 대역폭이 다르다. 진동은 공개 데이터에 없으며 생성/사용하지 않았다. 원시 위치·속도와 차분 오차가 어떤 좌표·단위를 쓰는지도 실물 확인이 필요하다.
- 후속은 API 확인과 여러 실험 세션의 정상 수집, 정격 내 안전한 부하 실험, 세션 단위 독립 분할이 우선이다. 정상 기준·신호 동기화·배치 이동 대응은 새 데이터에서 검증한다. 평가 결과를 보고 같은 테스트에 맞춰 모델/threshold를 다시 조정하지 않는다.
- 미래 K-cycle 사건 위험도와 RUL은 이번 목표가 아니다. 공개 이상 강도 setting의 임의 연결을 시간 연속 고장 이력으로 취급하지 않는다.
